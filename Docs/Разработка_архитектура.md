# План реализации со стороны разработки

**Цель:** конкретный план рефакторинга существующего кода и добавления новых модулей под трёхфазный pipeline (калибровка ботов на de_dust2 → анализ PCG-датасета → автобалансировка по конкретному seed).

**Язык:** Unity 6000+ / C# / Python 3.x.
**Дата:** 26.04.2026.

### 1.2. Контракты между подсистемами (ScriptableObject и JSON)

| Артефакт | Тип | Содержимое |
|---|---|---|
| `MapGenerationProfile.asset` | ScriptableObject | Размер карты, диапазоны 6–9 PCG-осей, плотности укрытий, веса A* |
| `BotProfile.asset` | ScriptableObject | 10–15 поведенческих параметров (accuracy, reaction, fov, …) |
| `ZoneTypeWeightsConfig.asset` | ScriptableObject | Константы `(ZoneType, RoadType, BotRole) → weight` из НИР1 |
| `MatchSetupConfig.asset` | ScriptableObject | Префабы ботов, размер команд, длительность раунда |
| Per-match `match_<seed>_<idx>.json` | JSON | seed, winner, duration, kills per side, death heatmap, маршруты, дескриптор PCG-осей |
| Population checkpoint `gen_<N>.json` | JSON | Поколение GA: вектор параметров → fitness каждой особи |
| Dataset `dataset.csv` | CSV | Один матч = одна строка: PCG-axes + win/duration/kills/… |

### 1.3. CLI и точки входа

```bash
# Один матч на конкретной карте + профиле бота
Unity -batchmode -nographics \
  -seed 42 \
  -mapProfile Assets/.../MapGenerationProfile_default.asset \
  -botProfile Assets/.../BotProfile_Calibrated.asset \
  -matches 10 \
  -out runs/match_42.json

# Калибровка
python Tools/calibrate.py --reference de_dust2 --generations 30 --pop 25 --matches 10

# Дата-сет для регрессора
python Tools/run_dataset.py --seeds 0..49 --variations all --matches 10 --out runs/dataset.csv

# Автобалансировка конкретного seed
python Tools/autobalance.py --seed 7 --target-winrate 0.5 --regressor models/regressor.pkl
```

## 3. Pipeline по фазам (что в каком порядке делается)

### Фаза 0 — фундамент (Неделя 1)

**Цель:** воспроизводимая генерация + автоматическая разметка зон + работающие боты на сгенерированной карте.

1. **`ZoneTypeWeightsConfig`** — создать asset, заполнить значениями из НИР1 (с комментариями-обоснованиями).
2. **Spawn-зоны получают `teamSide`** (`Attacker`/`Defender`).
3. **`TeamSpawner`** — спавн ботов из префабов по `SpawnZoneComponent` соответствующей стороны.
4. **`MapGenerator` рефакторинг этап 1**: `Random.InitState(seed)`, разбиение на стадии, инстанцирование `MapZoneComponent`-объектов с правильными `roadToSite`/`roadType`, регистрация в `MapManager`.
5. **`PathFinder` (A\*)** заменяет biased random walk.
6. **Runtime NavMesh** — `NavMeshSurface.BuildNavMesh()` после инстанцирования геометрии.
7. **`MapGenerationProfile` v1**: размер, ширина путей, плотность укрытий, число сайтов (2/3), соотношение длин Main/Link, ширина choke points (3 базовые оси).
8. **Editor-скрипт `ApplyZoneWeightsEditor`** — пройтись по de_dust2, проставить веса из `ZoneTypeWeightsConfig`.

**Smoke test:** запустить генерацию с seed=42, увидеть, что 5 атакующих и 5 защитников появились в нужных спавнах и пошли по карте; запустить ещё раз с seed=42 — карта идентична.

### Фаза 1 — параметризация ботов и батч (Неделя 2)

**Цель:** одной командой 100 матчей с любым `BotProfile` на любом `MapGenerationProfile`.

1. **`BotProfile`** — все магические числа из `BotComponent`/`*TeamManager` сюда. 10–15 параметров.
2. **Утилитарная функция выбора зоны**: `score(zone) = w_role·zone.GetWeight(role) + w_progress·progress + w_safety·safety + w_intel·friend_density`. Веса — из `BotProfile`. Бот выбирает зону с максимальным score из доступных.
3. **Реализация остальных PCG-осей** в `MapGenerator`: асимметрия путей, размеры сайтов, промежуточные комнаты, профили плотности укрытий, расположение нейтральной зоны, (опц.) вертикальная вариация.
4. **`MapMetrics`** — рассчитывает дескриптор карты (12–15 чисел) после генерации.
5. **`MatchLogger`** — пишет per-match JSON.
6. **`BatchRunner` + CLI** — `Unity -batchmode -nographics -seed N -mapProfile X -botProfile Y -matches K -out path.json`.
7. **`Tools/profile_io.py`** — конвертация `BotProfile.asset` ↔ JSON, чтобы Python мог писать профили перед запуском Unity.

**Smoke test:** `python Tools/run_dataset.py --seeds 0..9 --matches 5` создаёт 50 матчей и итоговый CSV.

### Фаза 2 — калибровка на de_dust2 (Неделя 3)

**Цель:** `BotProfile_Calibrated.asset`, который даёт winrate 0.5 ± 0.05 на de_dust2.

1. **Подготовить de_dust2 как сцену для калибровки**: убедиться, что зоны размечены (если нет — `AutoMarkZonesEditor` или ручная разметка), `ZoneTypeWeightsConfig` применён, спавны имеют `teamSide`, бот-префабы зарегистрированы в `MatchSetupConfig`.
2. **`Tools/calibrate.py`**: CMA-ES (через `cma`-пакет) или DEAP, геном = вектор параметров `BotProfile`.
3. **Fitness:** `|winrate − 0.5| + α·duration_penalty + β·degeneracy_penalty + γ·variance_penalty`. Запуск Unity для каждой особи через batch.
4. **Чекпоинты популяций**, сохранение лучшего как `BotProfile_Calibrated.asset`.
5. **Графики сходимости** (matplotlib): mean fitness и best fitness по поколениям, эволюция значений ключевых параметров.

**Smoke test:** калибровка сходится за 30 поколений, итоговый `winrate` на de_dust2 в пределах 0.5 ± 0.05 на 50+ матчах.

### Фаза 3 — диверсифицированный датасет + анализ + регрессор (Неделя 4 часть 1)

**Цель:** научные графики корреляций + обученный регрессор для Фазы 4.

1. **`Tools/run_dataset.py`** — целенаправленные вариации: для каждой PCG-оси по 5–10 значений × несколько seed = 30–50 уникальных карт. Каждая прогоняется 10 матчей с `BotProfile_Calibrated`.
2. **`dataset.csv`** содержит per-match строки: PCG-axes + winrate + duration + kills + …
3. **`Notebooks/analysis.ipynb`**:
   - Распределение winrate (гистограмма, mean/std).
   - Scatter `axis vs winrate` для каждой из 6–9 осей.
   - Pearson и Spearman корреляции.
   - Heatmap фрагов на типичной хорошей и типичной плохой карте.
   - Сравнение «до / после калибровки» на de_dust2.
4. **`Tools/train_regressor.py`**: на агрегированных данных (одна строка = одна карта = одни параметры PCG, средний winrate из 10 матчей) обучить sklearn регрессор `winrate = f(axes)`. Кросс-валидация k-fold, сохранить `models/regressor.pkl`.

### Фаза 4 — автобалансировка (Неделя 4 часть 2)

**Цель:** для произвольного seed получить карту с winrate ≈ 0.5 за счёт автоматической подкрутки PCG-осей.

1. **`Tools/autobalance.py`**:
   - Принимает `seed` и `target_winrate=0.5`.
   - Генерирует initial-параметры по seed.
   - Запускает scipy/random search по подмножеству регулируемых осей (e.g., ширина choke, плотность укрытий, длина Link), минимизируя `|regressor.predict(axes) − 0.5|` с ограничениями диапазонов.
   - Возвращает финальные параметры PCG.
2. **Перегенерация карты** в Unity с новыми параметрами того же seed → валидационные 20 матчей.
3. **Сравнение predicted vs actual winrate** — ещё один научный результат (точность регрессора).
4. **Демо**: 5–10 примеров «до / после автобалансировки» на разных seed.

## 5. Стратегия миграции (порядок «не сломаем существующее»)

Чтобы не получить «всё лежит, ничего не работает» в середине:

1. **Сначала всё новое — без удаления старого.** `MapGenerator` остаётся, рядом появляется новый `PathFinder` и новые методы инстанцирования зон. Старые `[SerializeField]`-веса в `MapZoneComponent` остаются, добавляется поведение по умолчанию из `ZoneTypeWeightsConfig`.
2. **Постепенная миграция Inspector→ScriptableObject.** Параметры `MapGenerator` сначала остаются в Inspector, но дублируются из `MapGenerationProfile.Defaults`. После проверки — удаляем старые поля.
3. **`TeamSpawner` сначала на пустой сцене.** Создаём отдельную тестовую сцену `Generated.unity`, в ней нет заранее размещённых ботов, проверяем спавн с нуля. de_dust2 трогаем только когда `TeamSpawner` подтверждённо работает.
4. **CLI режим прячется за `#if UNITY_BATCH_MODE`**. Editor-сценарии не ломаются.

## 7. Что точно НЕ делаем (антискоуп)

- RL через ML-Agents (нет 4–6 недель и не нужно при наличии CMA-ES + регрессора).
- Multi-agent self-play.
- Обучение на demo-файлах CS/Valorant.
- Полная замена скриптовой логики бота на нейросеть. (Старая «Часть B — supervised classifier для бота» остаётся в перспективах работы.)
- Нестандартные топологии карт (3+ команды, асимметричные карты «атака vs оборона»).
- Голосовая координация ботов / симуляция комуникации.

## 8. Точка старта

После согласования с научруком — стартую с **Фазы 0, шаг 4** (`MapGenerator` рефакторинг этап 1: разбиение на стадии + инстанцирование `MapZoneComponent`-GameObject'ов + регистрация в `MapManager`).

Параллельно вы:
- Создаёте 4 ассета конфигов в Editor (10 мин).
- Создаёте префабы зон (30 мин).
- Устанавливаете `com.unity.ai.navigation`.
- Готовите Python-окружение (`pip install cma deap scikit-learn pandas matplotlib jupyter`).
- Делаете тестовый запуск пустой сборки Unity в headless-режиме из CLI.

Дальше идём по фазам 0→1→2→3→4 строго в этом порядке. Пропуск любой ступени ломает следующие.
